# 小红书 App 推广文案写作（通用方法论）

为任意 App 的某个功能页写一篇小红书种草推广文案：一张配图 + 一篇文案成对发布。方法论源于 8 篇已发布文案的实际验证（见文末来源），对工具类、习惯养成类、记录类 App 通用。

这是**纯方法论** skill，不含任何特定 App 的信息；具体 App 的（名称、CTA 句式、tag、落盘路径）由对应的 App 专属 skill 提供——有专属 skill 时先读它，再按本篇的方法论执行。

## 文案在营销链路中的位置

- 配图链路：市场 9:16 介绍长图 → 3:4 顶裁小红书图片（图片处理见 `xhs-promo-images` 类 skill）
- **本 skill：为该图片写配套正文文案**，一个功能一篇，一图一文配对发布
- 图文一致性是硬要求：配图上出现的界面元素、数字，文案必须直接引用同一组（图上「连续满35天」文案就写「连续满35天」），不编造图上没有的数字

## 固定骨架（8 段，逐段照写）

```
【App名·功能名】                     ← 1. 首行【】，App 名 · 功能名（4-8 字）

<痛点钩子：1-3 行反问/场景>           ← 2. 开头 — 问句或扎心场景，让目标用户对号入座

为什么要<做的事>？                    ← 3. 为什么 — 无序号「·」列表 3-6 条
· 不……，就容易……。
· 不……，就说不清……。
· <做>，才能把「我想做」变成「每天做什么」。

<App 名>怎么帮你<做的事>？            ← 4. 过渡 — 承上启下的一问

<emoji> <功能亮点>（5-8 字）          ← 5. 功能清单 — 4-6 条，每条 =
<一行解释，引用截图里真实的数字/文案>    emoji 短语 + 一行具象解释

🔒 <信任块标题>                       ← 6. 信任块 — 每篇必有，内容按 App 实际
<1-2 行隐私/安全说明>                   情况写（本地存储/无广告/开源/无账号等）

<金句收尾：1-2 行对仗短句>            ← 7. 收尾 — 价值升华，不是重复功能

<App 的固定 CTA 句式>                ← 8. CTA + tag — 固定句式，一字不改
#<App名> #<功能tag> #<场景tag1> #<场景tag2> #<平台tag>
```

## 写作特点

### 语气与句式
- **短句、口语、零术语**：不用「量化」「正反馈闭环」这类抽象词，说「心里有底」「拖延藏不住」「多巴胺瞬间分泌」
- **对仗/排比是主武器**：`不管理目标，就容易瞎忙` / `不管理目标，就容易拖延` / `管理目标，才能……`；收尾金句对仗：`把坚持变成星星，把星星变成心愿。`、`把目标写下来，只是开始；把目标管起来，才会实现。`
- **不 X 与 X 对照**：「为什么」列表全部用 `不……就……` 与 `……，才能……` 两种句式对半开
- **第二人称直接对话**：「你会有强烈的动力去守护它」「孩子发育情况心里有底」

### 数字与具象化
- **引用截图中的真实元素**：数字、天数、成绩、参考区间——一律来自真机截图，不编造
- **枚举具体场景代替抽象描述**：`学习、健身、读书、早起、学英语、攒钱、戒熬夜……`、`看一部电影、喝杯奶茶、买本喜欢的书……`
- **「」里放产品原话**：直接引用 UI 文案/界面术语，如遇见「辰」

### 与配图联动（小红书图文特性）
- 文案要点名图上的东西：「看着连续打卡的“🔥31天”」「走到特定节点（比如图中的礼物盒）」「就像图里记录的」——读者看图即可对上文字
- 一篇只讲一个功能页，文案主题与配图标题同源
- **emoji 与画面元素同款**：🔥（火焰连击）、🎁（礼物盒）、📏（身高）——与界面/图片元素呼应，不乱选

### 必守约定
- **信任块每篇必带**：固定版式 + 按 App 情况组织内容（数据存储在哪、有无内购/广告/账号、隐私谁说了算）；数据越敏感，信任块说得越重
- **涉健康/财务/儿童需免责**：按主题加「（温馨提示：……仅供参考，不构成 XX 建议哦）」
- **篇幅 1100–1900 字符（约 30–40 行）**：功能多的页可长，简单的页可短，但骨架段落一个不少
- **纯文本排版**：不用 markdown 加粗/标题，靠空行分段 + 「·」列表 + emoji 行首，适配小红书正文框

## 流程

1. **看图定主题**：配图 + 图上的 title/subtitle/特征胶囊，确定功能名与图上可见的真实元素/数字
2. **定目标人群与痛点**：这个功能给谁、解决什么具体场景（如「忙碌时容易忘」）——开头钩子必须来自真实场景，不堆功能
3. **按骨架写正文**：8 段逐段填，功能亮点条目从截图中挑最有卖点的 4-6 个
4. **自检**（对照下面清单）
5. **落盘**：按 App 专属 skill（若有）约定的目录与命名存放；没有专属约定时，与配图同目录、同名前缀存放

## 自检清单（发布前逐项过）

- [ ] 首行【App名·功能名】，与配图标题同功能
- [ ] 开头是痛点反问或场景，≤3 行
- [ ] 「为什么」列表 ≥3 条，`不/才` 句式对照
- [ ] 功能条目自带 emoji，解释里至少 1 处截图真实数字/元素
- [ ] 🔒 信任块存在且说法与 App 实际一致
- [ ] 收尾是对仗金句，不是功能复述
- [ ] App 固定 CTA 句式在收尾块
- [ ] tag ≥4 个：App 名 + 功能 + 1-2 场景 + 平台
- [ ] 篇幅 1100–1900 字符，纯文本无 markdown 标记
- [ ] 图文元素一一对应（图上有的文案提了，文案提的图上有）
